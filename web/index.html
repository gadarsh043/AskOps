How it works

From URL to working agent in three steps

1

Connect your website

Paste your company URL. AskOps scrapes the site, extracts relevant pages, chunks the content, and generates vector embeddings automatically via Gemini.

2

Choose a persona

Select who you are for the demo — employee or HR manager. Each role gets different tool access, enforced at the Postgres level before any tool runs.

3

Ask anything

The agent answers policy questions from your knowledge base, processes PTO requests, creates IT tickets, and routes approval emails to the right inbox.

Capabilities

Everything a service desk needs, built in

No configuration files, no deployment pipelines. The full tool catalog is available from day one.

PTO requests

Employees request time off in natural language. The agent checks balance, validates dates, and emails the approval link to the manager.

Policy answers

Questions about remote work, expenses, benefits, or IT security are answered directly from your scraped knowledge base with source citations.

IT ticket creation

Employees describe issues in natural language. The agent categorizes, titles, and creates a support ticket with appropriate priority.

Approval emails

PTO requests trigger an email with a one-click approval link. Managers approve or reject from inbox — no login required. Tokens are single-use and expire in 48 hours.

Role-based access

HR managers see all PTO requests, salaries, and tickets. Employees see only their own. Access is enforced in Postgres, not the system prompt — it cannot be bypassed.

Live metrics

Every tool call is logged with status, latency, and employee code. CSAT from thumbs up/down. Accuracy from success/error ratio. Denials logged for audit.

Access control

Role-based permissions, enforced in the database

The agent calls current_identity() before every tool call. It reads from the active session, not from what the user claims in chat. Prompt injection cannot change what tools return.
